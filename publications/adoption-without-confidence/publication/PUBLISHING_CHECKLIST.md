# Publishing Checklist

## Required before posting

- [ ] Publish or make public the code repository.
- [ ] Upload the open research note.
- [ ] Replace the placeholder links in the launch copy.
- [ ] Confirm title, byline, date, and Imagination Applied attribution.
- [ ] Confirm Figure 1 and Figure 2 render clearly on desktop and mobile.
- [ ] Add the supplied alt text to both figures.
- [ ] Check every public link.
- [ ] Keep the causal and representativeness disclaimers intact.

## Strongly recommended

- [ ] Ask one independent reviewer to run the replication checklist.
- [ ] Create a versioned repository release.
- [ ] Add a DOI through Zenodo or OSF.
- [ ] Enable comments or provide a correction contact.
- [ ] Pin the methods and code link beneath the social post.

## Final editorial guardrails

- [ ] “Favorable stance” is used for analytic claims.
- [ ] “Sentiment” is used only as the accessible hook or Stack Overflow's label.
- [ ] Daily use is described as reported use.
- [ ] Trust is described as trust in output accuracy.
- [ ] The unsure/indifferent reversal remains visible.
- [ ] Trust is described as adding a small positive amount after stance.
- [ ] Cross-validation is not described as future forecasting.
- [ ] The result is not called causal, universal, or a proven first.

## Post-publication

- [ ] Archive the exact public files.
- [ ] Record publication URLs and date in `CITATION.cff`.
- [ ] Log material corrections in `RELEASE_NOTES.md`.
- [ ] Preserve earlier versions rather than silently overwriting them.
